# Data model

Database: `%LOCALAPPDATA%\NovelRAG\novelrag.db`; override the data directory with `--data-dir <absolute-path>` for isolated tests or portable profiles. Timestamps use UTC round-trip text; UI displays local time.

- Projects: integer ID, unique case-insensitive name, created/updated UTC and archived metadata. Rename preserves creation/archive state and updates UpdatedAt. Project archive metadata does not implicitly archive its ideas; this version adds no project archive UI. Deletion sets Ideas.ProjectId to null rather than deleting notes.
- Ideas: monotonic AUTOINCREMENT ID, nullable project FK, content, created/updated UTC, archived flag, revision and nullable Type mapped in Idea/IdeaDraft. A new draft defaults to null; a null Type on an edit preserves the stored value for compatibility with editors that do not expose it. A nonnull value sets it; there is no type-clearing UI in this batch. Content is 1–200000 characters; edits increment revision and invalidate embeddings transactionally.
- Tags: integer ID, unique case-insensitive name, created UTC, 1–100 characters. Rename preserves creation time. Names are trimmed; SQLite NOCASE provides ASCII case folding, not full Unicode case normalization.
- IdeaTags: normalized many-to-many composite key, cascading association deletion. A note can have up to 40 tags.
- Embeddings: idea FK, revision, chunk ordinal/text, model name/digest, dimension, chunker version, float32 BLOB and created UTC. New writes supply current UTC if no timestamp is provided. Only one active model's chunks are stored per note. Original notes are always authoritative.
- Settings: reserved transactional key/value settings table; current desktop preferences/bootstrap configuration are in settings.json.
- SchemaMigrations: version and applied-at timestamp. PRAGMA user_version is also checked before startup mutates anything.
- IdeasFts / IdeasTrigram: external-content FTS5 tables, synchronized by insert/update/delete triggers. Short queries use literal substring membership to retain punctuation and Chinese terms.

Current schema version is 2. Migration 1 creates the original schema; migration 2 adds entity metadata without changing IDs, relationships, note text/times, Type or vectors, and retains both FTS table definitions. An existing v1 database gets a SQLite online safety backup (`novelrag.db.pre-migrate-<unique-id>.bak`, including committed WAL), then all v2 changes commit in one transaction. Failure/cancellation before commit rolls back. Repeated initialization does not rerun migration. New databases use the same schema steps, so their final structure matches upgraded files. Unknown future versions are rejected without migration.

During a live v1 upgrade, both derived FTS indexes are rebuilt from Ideas inside the same transaction before integrity checks. This lets profiles with stale indexes start normally while the pre-migration copy retains their original state. Restore candidates remain strict: inconsistent FTS data is rejected without replacing the live database.

Old projects derive CreatedAt from the earliest linked idea and UpdatedAt from the latest linked idea modification. Old tags derive CreatedAt from their earliest linked idea. Unlinked entities and old embeddings use migration UTC; these are fallback timestamps, not recovered historical dates. Existing projects start Archived=false. New records write real UTC values. Schema comparison normalizes CRLF/LF only, preserving strict table/index/trigger validation.

Archive excludes notes from ordinary search but retains their data and exports. Explicit delete cascades tags/embeddings and removes FTS entries. Renaming tags retains associations. Project/tag deletion does not mutate idea text.

JSON export version 2 adds project/tag metadata and Idea.Type to the existing IDs, notes (including archives), relations, timestamps and revisions. Consumers that require version 1 must accept the new version/fields before using these exports; no JSON import is added. Rebuildable vectors remain excluded. Markdown includes the optional Type alongside readable content grouped by project; JSON/SQLite retain full entity metadata. Neither exporter can target the live database or SQLite sidecar files. Raw database backup preserves the complete database, including indexes and embedding timestamps.

Restore snapshots a v1/v2 backup through SQLite's backup API into a unique staged candidate, validates its canonical schema, upgrades v1 in that candidate, then checks integrity, FKs and both FTS indexes against external content. The original backup is not migrated or overwritten. Only after validation does it preserve `novelrag.db.pre-restore-<timestamp>.bak` and replace the live database through SQLite backup, with rollback from the safety copy on replacement error. Future versions and altered/incomplete schemas are rejected. Keep independent backups on another drive for disk-failure protection.

Settings → 数据与备份 → 修复关键词索引 works with AI disabled. Both IdeasFts and IdeasTrigram are rebuilt and validated in one transaction under the store gate; original records and timestamps remain unchanged. Cancellation is checked between SQLite statements and before commit; an already-running statement may finish before cancellation returns. A failure or accepted pre-commit cancellation rolls back both indexes. The UI joins AI monitoring/requests/indexing through the maintenance gate and retains draft-close confirmation before starting. This repairs index/content inconsistency, not missing schema objects or arbitrary database-file corruption. FTS rebuild and rank=1 external-content checks follow the [SQLite FTS5 commands](https://www.sqlite.org/fts5.html#the_integrity_check_command).
